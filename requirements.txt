# Agent SDK used by scripts/orchestrate.py. PINNED (==, not >=) — deliberately,
# not stale. orchestrate.py's ClaudeAgentOptions never set setting_sources, so
# the SDK defaulted it to None, which subprocess_cli.py serializes as the same
# "--setting-sources ''" the CLI sees for an explicit empty list. In 0.1.59 and
# earlier that empty value is treated as "omitted" (user + project + local
# settings load, so project .claude/settings.json hooks fire — including
# anonymize-guard.py and mcp-query-guard.py). The SDK docs state this behavior
# flips after 0.1.59: an empty setting_sources then DISABLES filesystem
# settings instead. Because None and [] serialize identically, bumping past
# that boundary would silently stop every project hook firing in pipeline
# runs, with no error. orchestrate.py now also passes setting_sources
# explicitly (see run_agent()'s ClaudeAgentOptions), which makes hook loading
# independent of this default — but keep this pin as the second line of
# defense: do not remove it without re-verifying the setting_sources fix is
# still in place and hooks still fire end-to-end.
claude-agent-sdk==0.1.39

# spaCy NER model Presidio's analyzer loads for name/entity detection. PINNED

# after re-running the D10 measurement.
