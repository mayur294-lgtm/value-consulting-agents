## From the live BDO managed-hosting run (2026-08-20) — first real engagement through `/proposal-builder`

**Consultant request, to apply on the next revision cycle (not built yet, logged 2026-08-20):**

- [done v9] **ACT 4 should emit TWO HTML files, not one.** Today the client proposal is HTML and everything internal is Markdown/JSON. On this run that produced **seven** internal artifacts (`INTERNAL_strategy_brief`, `INTERNAL_negotiation_plan`, `INTERNAL_deal_desk_fields`, `INTERNAL_deal_state.json`, plus a decision pack, contract review and arithmetic audit). **An AE will read one briefing, not seven files.** Add a second rendered output — an **internal AE briefing HTML**, same Frontline shell as the client doc, carrying exactly four things:
  1. **What the proposal says and why it is shaped that way** — a short walkthrough of each section and the job it does
  2. **Decisions the AE must make before it can be sent** — one table, each with options and a recommendation
  3. **Points to keep in mind in the room** — what we hold, what is weak, what must not be said (e.g. wording that would waive a live claim)
  4. **The commercial step-downs to close** — the ladder from `strategy.json`, expressed in the currency the AE actually negotiates in (monthly fee, not TCV %), with the extract paired to each step
  The Markdown internals stay as the audit trail; the HTML is the thing the AE opens. Consultant: *"one is for your internal use... and then this external facing one."*

**Skill gaps this run exposed (evidence for the `/proposal-builder` feedback cycle):**

- [done v9] **No contract-review gate in ACT 0.** Three of the four pricing lines quoted to the client had **no basis in the signed order form** — and this was only caught on the fourth revision, when the consultant happened to supply the contract. ACT 0 should *require* the order form / master agreement and check every quoted rate against it before a number reaches the client. On this deal: $8,050/5TB, $165/500k messages and $5,750/staging appear nowhere in POF 012045; the POF states two limits and prices neither; and it prices extra runtimes at $2,500, contradicting the $5,750 being asked.
- [done v9] **No arithmetic audit of upstream material.** The skill assumes the numbers handed to it are sound. Six errors were found in material the bank already held — a deck total omitting one of its own rows, a bundle-count convention that changes mid-series, an 18-vs-17-month mismatch, and a flat average applied across a 9.4× ramp. Add an audit step before the deal brief.
- [done v9] **Forecasting is entirely absent from the skill.** Nothing covers multi-period forecasting, growth-rate selection, or the fact that banded/slab pricing is a **step function** (so mean(f(x)) ≠ f(mean(x)) — this bit us and confused the client-facing reconciliation). This deal needed all three. Consider a forecasting section in the knowledge base: derive rates per driver from observed data, never a blanket % on the bill; prefer an intensity anchor tied to the client's own projections; model optimisation as a level cut, not growth-rate damping.
- [done v9] **The single-headline / two-scenario shape broke.** ACT 1 Gate 6 assumes two scenarios and one figure. This deal needed **two settlement periods × two options** (2026 measured + 2027 forecast). Generalise the mandate to "exactly two options, across N agreed periods".
- [done v9] **Elasticity exposure default is too narrow.** Conservative (volume + term) was wrong here — the whole persuasion mechanic was exposing every driver, including a **derived** one (RPS from MAU × measured intensity). Support derived drivers and document when to open the dial.
- [done v9] **No hook for consultant/client copy rules or audience register.** `proposal-narrative.md` §4 has voice rules, but there is no way to inject a per-consultant house style sheet or an audience-register parameter (this run needed a less-direct register for a Philippine bank, plus a house rule banning ", and" constructions). Add both as brief inputs.
- [done v9] **`/proposal-longform` has no charting.** A 20-row schedule table had to be hand-built into four SVG small multiples with a hover layer. Add a chart component to the template (small multiples + crosshair tooltip), and keep a table view behind a disclosure for accessibility.
- [done v9] **CHECKPOINT 3 leak scan is naive substring matching.** `CRO` matches "across"/"crossed"/"scroll"; `anchor` matches `text-anchor` in SVG. Specify **word-boundary** matching, and add `absorb` / `written off` / `waived` to the list — on this deal those words would have conceded a live recovery claim in writing.
- [done v9] **Footer attribution should read "Prepared by Backbase", not "Prepared by Backbase Value Consulting".** The template's `doc-footer` and readout `ro-foot` both name the internal team on a client-facing document. Client artifacts carry the company, not the function. (consultant, 2026-08-20)
