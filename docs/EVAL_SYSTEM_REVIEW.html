Section 01

The model

Two axes — WHAT gets scored × WHEN it's scored. Every cell is an eval.

What Dev-time — gate Runtime — consultant Monitor
① Every agent Regression — BLOCKS Live on real input — FLAGS Trend
② Every handoff Contract — BLOCKS Live at each boundary —
③ Every deliverable Rubric — BLOCKS On real artifact — FLAGS Drift → issue

Dev-time

gate

Runs from git via run_experiment.py. Offline, deterministic, blocks the PR until green.

Runtime

consultant

Runs from Langfuse on live traces. Scores the real engagement run and flags low scores — never blocks.

Monitor

drift

Watches quality-over-time on the Langfuse dashboard; drift raises an issue.

Section 02

Where evals live

One definition, two homes. Authored and reviewed in git, then mirrored to Langfuse via sync_to_langfuse.py.

Git — the rulebook

source of truth

Judge prompts (.md) + code rubrics (.py) + registry.yaml + goldens. Reviewed in PRs, versioned, gate CI offline. This is what you approve.

Langfuse — the scoreboard

live engine

The same judges synced in as versioned prompts + datasets. Auto-scores live consultant runs and shows trends and drift on dashboards.

Section 05

How people use it

Three roles, three relationships to the eval suite.

🛠️
Developer (changes an agent)

One-time setup_dev.sh. Every change routes through bb-prd → … → bb-refine; evals are the verify gate; the PR is blocked until green.

📋
Consultant (runs cortex)

Just runs agents and the pipeline. Evals score the run live and flag low scores in the run report — never block the engagement. (runtime layer pending)

📊
You (review & trend)

Approve evals in PRs (git). Watch quality-over-time and drift on the Langfuse dashboard.
