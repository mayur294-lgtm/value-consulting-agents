# Positioning History — Archived Backbase Positioning Narratives

**Purpose:** Archive of superseded positioning narratives for historical reference.

## Convention

The most recent positioning narrative file at the **top level of `/knowledge/`** is **canonical**. Cortex agents use it for all new POVs, ROI models, capability assessments, and roadmaps.

When a new version of the positioning narrative supersedes the current one:
1. The current file (e.g. `banking_os.md`) moves to this folder, renamed with version suffix (e.g. `banking_os_v4_2026-06.md`)
2. The new version replaces the original filename at the top level of `/knowledge/`
3. This README is updated with a one-line entry pointing to the archived file and noting what changed

## Why we keep history

- **Active client engagements** that started mid-flight on an earlier narrative may need the prior framing for continuity
- **Historical engagement learnings** in `/knowledge/learnings/` reference older taxonomies — archived narratives let agents interpret them correctly
- **Migration accounts** where the customer was originally pitched on prior positioning
- **Audit trail** for how Backbase positioning has evolved over time

## Rules for agents

- **Never use an archived positioning narrative as the basis for a new POV, ROI model, or roadmap.** Always use the canonical current file at `/knowledge/`.
- Archived files are **reference-only** — for understanding what was said in past engagements, not for generating new content.
- If a consultant explicitly asks for the prior framing (e.g., to maintain continuity in an existing client engagement), use the archived version and flag the choice in the engagement journal.
